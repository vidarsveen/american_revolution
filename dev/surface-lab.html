surfaces — what a pack actually pays for

Does a pack that does not declare the map surface load map/ at all?
This is the one measurable payoff of the surface refactor, and it is easy to claim and easy to lose: a single convenience import of engine/surfaces/map.js anywhere on the path from index.html puts the whole map module back in the graph of every pack, silently, with everything still working. So it is measured on performance.getEntriesByType('resource') — what the browser actually fetched — and never inferred from reading the source.

And the falsification: the same page with the surface put back (?drop=) must report a non-zero count. A bench that says zero in both runs is measuring nothing.

And: a cue that arrives before the surfaces do — is it held, or lost?
import() is asynchronous and mountStage() is called synchronously, so on the FIRST mount of a page there is a window in which no surface is up. Dropping cues there would make the picture depend on how fast the network was, which is a history of events by another name. They are queued in order and released on mount, and resetStage() throws the queue away. This page is the only place that window exists, because every mount after the first is served from the module cache and is entirely synchronous.
